# #570 配信シーンごとのカメラ割り当て — 設計案（実装・配備前）

オーナー要望: 「配信中の切り替えは至難の業だから、シーンごとにカメラパーツにカメラソースを事前に割り当てられるようにして欲しい」

この文書はオーナー確認用の設計案で、本番コードは変えていない。動く見本は [prototype.html](assets/live-camera-slots-570/prototype.html)（オフラインで開ける。カメラ映像はすべて色付きの canvas で描いた「ダミー」）。

## 1. 結論（提案するモデル）

- 配信セットのカメラパーツには、機器そのものではなく**カメラ番号**（「カメラ1」〜「カメラ4」）を持たせる。番号には任意で**呼び名**（例: 登壇者、会場）を付けられる。呼び名はセット共通。
- **どの機器をどの番号にするか**は、配信するPCのブラウザだけが知っている。配信セットごとに localStorage へ保存し、配信前に一度だけ選ぶ。
- 選ぶ場所は**配信コントロール画面の「カメラの割り当て（このPC）」**。同じPCで開いている配信画面にすぐ反映する。配信画面右下の歯車にも同じパネルを置き、コントロールを別の端末で操作するときに使う。
- 配信画面は、**セットで使う機器を開いたまま**にする（最大4台）。シーンを切り替えた瞬間に正しいカメラが映る。
- 割り当てのない番号は**既定のカメラ**で映す。「未割り当て」の警告は配信コントロールにだけ出し、配信画面（OBS が取り込む画面）には出さない。
- 配信中にカメラを切り替える操作は作らない。シーンを押すだけで、シーンに置いたカメラ番号の映像になる。

### なぜ機器ID（deviceId）をセットに保存しないか

ブラウザの deviceId は PC とサイト（オリジン）ごとに違う値で、サイトデータを消すと変わることもある。配信セットを編集するPCは、たいてい配信するPCとは別。別のPCで選んだ deviceId をセットに保存しても、配信PCでは一致しない。そこでセットには「意味」（カメラ1 = 登壇者）だけを持たせ、「実際の機器」は配信PCで結び付ける。

## 2. 現状（main 8ddb842 で確認）

- `apps/web/src/pages/LiveScreenPage.tsx` は `getUserMedia` でストリームを1本だけ開く。機器は localStorage `eventer-live-camera-device` に保存している。設定は右下の歯車の中にあり、歯車はカーソルを動かしている間しか出ない。オーナーも場所を尋ねる必要があった。
- すべての camera 要素が、`CameraVideo` を通して同じ1本のストリームを使う。
- camera 要素のスキーマは `packages/shared/src/liveSets.ts` の `fit` と `radius` だけ。
- `LiveAddPartDialog.tsx` では、カメラを選ぶと設定を挟まずにすぐ置く（`liveParts.ts` の `ADD_WITHOUT_SETTINGS`）。`LiveElementPanel.tsx` のカメラ設定は、フィット・角丸・説明文だけ。
- 配信セットの `content` は D1 の `live_set.content` に JSON 文字列で保存される（`0019_live_sets.sql`）。サーバーは保存時に `liveSetContentSchema` で検証する。

## 3. 体験の流れ

### 3.1 編集: カメラパーツに番号を割り当てる（どのPCでもよい）

見本: `#editor`、`#add`

1. 「パーツを追加」→「カメラ」を選ぶと、すぐには置かず**2段目の設定**に進む（画像や時計と同じ流れ）。右側の「映すカメラ」で番号を選ぶ。
   - 既定の番号: 開いているシーンにカメラがまだなければ「カメラ1」。すでにあれば、そのシーンでまだ使っていない一番小さい番号（ワイプ＋全画面のような2台構成を、選び直さずに作れるように）。
   - 候補は、このセットで使っている番号と「＋ 新しいカメラ（カメラN）」。上限は4。
   - 「呼び名（任意）」を入れられる。例は「登壇者、会場」。
   - 「このカメラを置く」で置く。
2. 置いたカメラパーツを選ぶと、右の要素設定の先頭に同じ「映すカメラ」選択と呼び名の欄が出る。その下に、今までどおりフィットと角丸が並ぶ。
3. キャンバス上のカメラ枠には、番号の色バッジと「カメラ1 · 登壇者」を出す。これで、どのシーンでどのカメラを使うかが一目で分かる。左のシーン一覧にも、各シーンで使う番号の小さなバッジを出す。
4. 案内文「どのカメラ機器を『カメラ1』『カメラ2』にするかは、配信するPCの『配信コントロール → カメラの割り当て』で一度だけ選びます」を、今の `cameraHint` の代わりに出す。
5. デザイン部品（提灯カメラ額など）は、今までどおり選んだ時点で置き、中のカメラは番号なし（= カメラ1）になる。番号は置いたあと要素設定で変える。
6. スマホでは、シーン一覧を横スクロールの帯にし、キャンバスと設定を縦に並べる（見本 `mobile-editor-slot.png`）。

**編集PCの実機名は候補に出さない**（判断は §6-5）。

### 3.2 配信PCで一度だけ: カメラの割り当て

見本: `#mapping`

1. 配信PCで配信コントロール（`/events/:id/live/control`）を開く。配信セット選択の下に「カメラの割り当て（このPC）」の枠を出す。セットにカメラパーツが1つもなければ枠は出さない。
2. 行は、**セットで実際に使われている番号**ごとに1つ。各行の中身:
   - 番号バッジ、「カメラ1」、呼び名、使っているシーン名（例: 講演・対談）
   - 機器のドロップダウン（「未割り当て（既定のカメラで映す）」＋ このPCのカメラ一覧）
   - 小さなライブプレビュー（128×72）。未割り当てなら既定のカメラを映し、「既定」と重ねて表示する。
3. 選ぶとすぐ localStorage に保存する。同じPCで開いている配信画面には、1秒以内に反映する。保存ボタンはない。
4. 枠の右上に「このPCの配信画面: 開いています / 見つかりません」を出す。「見つかりません」のときは「配信画面を開く」を案内する。
5. 未割り当ての番号があると、枠の下に黄色の警告「カメラ2 が未割り当てです。このまま配信すると既定のカメラが映ります。この表示は配信コントロールにだけ出て、配信画面には出ません。」を出す。
6. カメラの使用許可をまだ出していないPCでは、一覧の代わりに「カメラの一覧を表示するには使用を許可してください」と「許可する」ボタンを出す。ブラウザは許可前だと機器名を返さない。
7. プレビューは、枠を開いている間だけ低解像度で開く。枠を畳んだら止める。枠は、全番号の割り当てが済んでいれば畳んだ状態で始め、未割り当てがあれば開いた状態で始める。

**配信画面右下の歯車**にも同じ内容のパネル（コンパクト版）を置く。今の「カメラ1台の選択」はこれに置き換える。コントロールをタブレットなど別の端末で操作するときは、こちらで割り当てる。

### 3.3 配信中: シーンを押すだけ

見本: `#scene-a` → `#scene-b`

- コントロールでシーンを押すと、配信画面がそのシーンに切り替わる（今のまま）。講演シーンではカメラ1（登壇者）がワイプに、対談シーンではカメラ2（会場）が全画面に、カメラ1が丸抜きで映る。
- セットで使う機器はすべて開いたままなので、切り替えでカメラが暗くなったり待たされたりしない。シーンの 400ms フェードだけで切り替わる。
- コントロールのシーングリッドにも、使う番号の小さなバッジを出す。
- 配信中の割り当て変更はできるが、想定の使い方ではない。変えた場合は、配信画面がその番号の機器だけを開き直す。

### 3.4 失敗したときの表示

| 状況 | 配信画面（OBS に映る） | 配信コントロール（運営者だけが見る） |
| --- | --- | --- |
| 番号が未割り当て | 既定のカメラの映像（警告は出さない） | 黄色「カメラN が未割り当て。既定のカメラが映ります」 |
| 保存した機器がこのPCに見つからない（抜けている・IDが変わった） | まず同じ機器名のカメラを探して映す。なければ既定のカメラ | 黄色「カメラN に選んだ『USBカメラ A』が見つかりません。既定のカメラで映しています」＋ ドロップダウン |
| 機器を開けない（他のアプリが使用中・許可なし） | そのカメラ枠だけ今の「カメラ待機中…」表示 | 赤「カメラN を開けません（他のアプリが使用中の可能性）」＋「再試行」 |
| 配信中に抜けた（track の ended） | そのカメラ枠が「カメラ待機中…」になる。挿し直すと `devicechange` で自動で開き直す | 赤「カメラN の映像が止まりました」 |
| このPCに配信画面がない | — | 「このPCの配信画面: 見つかりません」 |

配信画面は OBS のウィンドウキャプチャでそのまま取り込まれる。そのため、配信画面の上には警告を重ねない。今の配信画面には、チャットや時計の失敗を赤い帯で重ねる表示があるが、カメラの警告はそれに加えない。歯車パネルを開いたときだけ、パネルの中に同じ警告を出す。

## 4. データモデル

### 4.1 配信セット（D1 の JSON、共有される）

```ts
// packages/shared/src/liveSets.ts
export const LIVE_CAMERA_SLOTS = [1, 2, 3, 4] as const;

liveElementSchema = z.object({
  // …既存
  /** camera: 映すカメラ番号。未指定は 1（#570 以前の要素） */
  cameraSlot: z.number().int().min(1).max(4).optional(),
});

liveSetContentSchema = z.object({
  scenes: …,
  /** カメラ番号の呼び名（セット共通・任意）。機器 ID は持たない */
  cameras: z.array(z.object({
    slot: z.number().int().min(1).max(4),
    label: z.string().max(20),
  })).max(4).optional(),
});
```

- 追加する2つの欄はどちらも optional。`content` は JSON 文字列の列なので、**D1 のマイグレーションは要らない**。
- 番号のない既存の camera 要素は、読むときに「カメラ1」として扱う（`el.cameraSlot ?? 1`）。データは書き換えない。既存セットは何もしなくても、今と同じ1台の動きになる。
- 呼び名はセットに1つずつ持つ。同じ番号を使う別シーンのパーツにも同じ呼び名が出る。呼び名を要素ごとに持つと、「カメラ1」がシーンによって違う名前になり、割り当ての画面で迷うため。
- 上限を4台にする理由: USB の帯域と、同時に開いたときの PC の負荷。4台を超える構成は OBS 側で組む範囲とする。
- サーバーは zod の既定動作で未知のキーを落とす。そのため、共有スキーマの変更とサーバーの配備は同時に行う。

### 4.2 配信PCの割り当て（localStorage、そのPCだけ）

```text
キー:  eventer-live-camera-map:<liveSetId>    // ビルトインは "default"
値:    { "1": { "deviceId": "…", "label": "USB Camera A" }, "2": { … } }
```

- 配信セットごとに持つ。同じPCでも、セットによってカメラの意味が違ってよいため。
- `label` は、deviceId が変わったとき（サイトデータの削除など）に同じ名前の機器を探し直すために持つ。
- 移行: 割り当てのないセットを初めて開いたら、今の `eventer-live-camera-device` の値をカメラ1の初期値にする。今1台で配信している人は、何もしなくても同じカメラが映る。
- 配信画面とコントロールは同じオリジンなので、localStorage の `storage` イベントで反映する。配信画面からの状態通知（開いている機器・エラー・機器一覧）には `BroadcastChannel("eventer-live-camera:<eventId>")` を使う。サーバーには何も送らない。

## 5. ストリームのライフサイクル（配信画面）

1. 配信セットを読み込んだら、全シーンのカメラ要素から使う番号の集合を作る。
2. 番号を機器に解決する: 割り当て → 保存したIDがあればそれ → 同じ名前の機器 → 既定のカメラ。
3. **異なる機器ごとに `getUserMedia` を1回だけ**呼ぶ。複数の番号が同じ機器に解決されたら、1本のストリームを共有する。未割り当ての番号が複数あっても、既定のカメラは1本だけ開く。
4. camera 要素は、自分の番号から機器を引いて `<video srcObject>` に流す。
5. 配信セットを切り替えたとき、割り当てを変えたとき、要素を消したときは、使わなくなった機器のストリームを `track.stop()` で止める。配信画面を閉じたら全部止める。
6. 映像は `width: { ideal: 1280 }, height: { ideal: 720 }` で開き、4台分の負荷を抑える。
7. `devicechange` のたびに機器一覧を取り直し、開けていない番号を開き直す。

**判断: セットで使う機器は全部開いたままにする**（シーンごとに開け閉めしない）。

- `getUserMedia` で開くと、映るまでに0.3〜2秒ほど黒い（またはプレースホルダーの）枠が出る。シーン切り替えのたびにこれが映ると、まさにオーナーが避けたい「配信中の事故」になる。
- 他のアプリが使用中、許可がない、といった失敗は、開くときに起こる。開いたままにすれば、**配信を始める前、配信画面を開いた時点で**失敗が分かる。シーンごとに開くと、失敗は本番の切り替えの瞬間に見つかる。
- 代わりに、PC の負荷とカメラのランプが付いたままになる。これは上限4台と 720p 指定で抑える。1台構成の人（ほとんどの人）には違いがない。

## 6. 判断とその理由

1. **セットには番号と呼び名、機器はPCごと**: 編集PCと配信PCが違っても成り立つ唯一の形（§1）。
2. **割り当ての入口は配信コントロール**: 配信前に必ず開く画面で、歯車のように隠れていない。コントロールには、配信セット・スライド・BGM の選択が既に並んでいる。前提として、**配信画面とコントロールは同じ配信PCで開く**ことが多いと考える。今のコントロールには「配信画面を開く」ボタンが別タブで開く形しかなく、OBS もそのPCで動いている。同じPCにあるかは「このPCの配信画面」の表示で分かる。別の端末で操作する場合は、配信画面の歯車で割り当てる。
3. **既存データはカメラ1**: 何も変えなくても今と同じ動きになり、マイグレーションも要らない（§4.1）。
4. **全部開いたまま**: §5。
5. **編集画面で実機名を候補に出さない**: 実機名を出すには、編集画面でもカメラの使用許可を求める必要がある。しかも編集PCは配信PCでないことが多く、出した名前は配信時に意味がない。同じPCで編集するときの手間は「呼び名を打つ」だけなので、許可の確認を増やすほどの得はない。実機名はコントロールの割り当て画面で見られる。
6. **警告は運営者の画面だけ**: 配信画面は丸ごと取り込まれるため（§3.4）。

## 7. 対象外

- OBS との連携（OBS のシーンやソースの切り替え、obs-websocket）
- 配信中にカメラを切り替える操作（シーンを分けて置くことで代える）
- 割り当てをサーバーへ保存すること、別のPCとの同期
- 5台以上のカメラ、音声入力の選択、解像度やフレームレートの設定画面
- 配信画面の上へ警告を重ねること

## 9. オーナーに確認したいこと

1. 配信画面とコントロールは、同じ配信PCで開く前提でよいか（コントロールをタブレットで操作する運用はあるか）。
2. 割り当てを配信セットごとに持つ案でよいか。それとも「このPCのカメラ1はいつもこの機器」とPC共通にしたいか。PC共通なら、セットを替えても選び直さずに済む。代わりに、セットごとに意味を変えられなくなる。
3. 上限4台で足りるか。
4. 呼び名はセット共通（カメラ1 = 登壇者、どのシーンでも）でよいか。
5. 未割り当てのとき既定のカメラで映す案でよいか。映さず「カメラ待機中…」にする案もある。安全側だが、配信に黒い枠が出る。
