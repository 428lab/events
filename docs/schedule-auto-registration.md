# 日程確定時の自動参加登録 (#513)

オーナー承認: 選んだ候補日に○/△の回答者を自動登録。既存登録は維持、×/未回答は追加しない。定員・抽選・必須アンケートなどを尊重し、主催者に登録結果/追加操作が必要な人を表示、本人に通知する。実装・stagingまで。本番は別承認。

## ルール

- 枠なしは参加確定、単一枠はその枠の通常ルールを適用。複数枠は勝手に選ばず本人へ枠選択を案内する。
- 先着はその候補への初回回答日時順（同時刻はuser ID順）で残席まで確定、残りはキャンセル待ち。○と△の間に優先順位は付けない。抽選は申込であり当選ではない。
- 既存メンバーの役割/状態を変えない。取消履歴は勝手に復活させず本人による再登録を案内する。
- 必須事前アンケートが未回答なら追加しない。締切後/終了済みも登録せず主催者への確認を案内。退会申請中ユーザーを除く。
- 回答画面と確定確認に動作を明記。匿名回答でも登録後は参加者名が表示される旨を回答前に説明する。個別結果はstaff専用APIで保護する。

## 原子性と再送

D1 batch（https://developers.cloudflare.com/d1/worker-api/d1-database/ のtransaction保証）で、受領記録・対象/状態の判定・メンバー・個人Entry/EntryMember・アプリ通知・日時更新を一括コミットする。失敗時は全部ロールバック。SQLが最新の回答/枠/取消/アンケートを参照し、人数分のWorkerサブリクエストを増やさない。

migration0088はイベント単位の確定受領記録とユーザー単位の結果表を追加する。完了後の同候補再送では登録/通知を繰り返さず保存済みの結果を返す。別候補の競合は409。明示的に調整を再開した場合だけ次の確定で記録を更新する。イベント/ユーザー削除はCASCADE。アカウント統合はイベント単位の勝者優先で結果を移す。

通常の本人joinも、先着/抽選状態を書き込み時に決定することで自動登録との定員競合を防ぐ。競合による既存メンバーへのINSERTは無視し、その実状態を返す。取消行の復活は `status='canceled'` を条件にし、同時再参加で後続リクエストが確定済みの自分を満員扱いして降格させない。自動登録のINSERT順を回答順に固定し、繰り上げは登録時刻が同じ場合にrowid順で判定する（既存の待機者の登録時刻は変えない）。

## 通知・表示

日程回答者には従来の日程確定通知を送り、対象者には参加確定/キャンセル待ち/抽選申込/要操作を追記する。アプリ通知は全員分をトランザクション内で保存する。メールは既存設定を尊重するbest-effortで、既存一括通知と同じ上限50件。自動登録からフォロワー向けの大量通知は追加しない。

主催画面は確定後に結果ダイアログを開き、後から「日程確定時の参加登録結果」で再表示できる。確定当時の記録であり、後日の取消や繰り上げは参加者一覧を見る旨を明記。従来の集計折りたたみ/公開設定は維持する。

## 検証

関連APIで対象候補の○/△だけの登録、既存/取消維持、権限、枠容量/抽選、追加操作、個人Entry、再送と並行確定を確認。通知INSERTの意図的失敗で日程と登録が巻き戻ることを検証する。FK追加の監査期待値を実数で1増加し、統合テストも実行。UIで状態を参加確定と誤表示しないことと履歴表示を確認する。

独立レビューで同時再参加の降格と待機列の同時刻順序を指摘され修正。2件の決定的な回帰テストを追加し、元のcf18fd3を隔離したコピーではそれぞれ失敗することを確認。修正版の関連API10件は成功。実WebKit390px/Chromium1440pxで104名の結果を使い、確定→結果ダイアログ→閉じる→再表示、状態の区別と横はみ出しなしを確認（業務APIはモック、iPhone実機受入とは別）。
