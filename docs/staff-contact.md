# 運営から個別に連絡する（運営から始める問い合わせ）

状態: 実装済み（オーナー依頼 2026-11-22「参加者に個別に連絡する手段が欲しい。登壇者に連絡がつかないリアルな問題が発生している」）。

## 何をするか

イベントの運営（確定スタッフ）が、そのイベントのメンバー1人に連絡を送る。相手は返信できる。
新しい仕組みは作らず、**イベントの主催者あての問い合わせ（D-EVENT-CONTACT、migration 0110）を運営からも始められるようにした**。
相手の画面は今の「お問い合わせ」一覧とスレッドのまま、運営の画面も今のイベントの「問い合わせ」のまま使う。

- 入口: 運営ページの参加者一覧の「…」→「個別に連絡する」、タイムテーブルの登壇者の名前の横の封筒（運営だけ）。
  件名（任意。空ならイベント名）と本文（問い合わせと同じ上限）を書いて送ると、運営側のスレッドが開く。
- API: `POST /api/events/:id/inquiries/staff-contact {userId, subject, body}`（確定スタッフだけ。201 `{id}`）。

## 決めたこと（オーナー決定 2026-11-22）

1. 問い合わせのスレッドを使う（運営から始められる形）。
2. 送れる相手は、そのイベントのメンバー全員（参加者のどの状態も、登壇者・審査員・観覧者・運営も）。
   ただし自分自身・キャンセルした人・退会した人・いまそのイベントを見られない人には送れない（404 `not_member`）。
   書き込み時に、送る人が確定スタッフであることと相手の条件を同じ D1 batch で確かめる（`inquiriesRepo.createStaffContact`）。
3. 件数の上限は無い。本人が送る問い合わせの上限（1イベント未完了3件）には、運営から始めた連絡を数えない。
4. 運営 → 相手: ベル通知と、相手がメール通知をオンにしていればメール（相手の言語、docs/i18n-notices.md）。
   **Webhook には流さない**（運営が書いた中身で、個人あてのため）。
5. 相手の返信:
   - Webhook に流す（種類は「問い合わせ」。題名は「運営からの連絡への返信: <イベント名>」。本文は全文。docs/webhooks.md）。
   - メールは**連絡を始めたスタッフだけ**に送る。ほかの運営はベル通知と Webhook で気づける。
     始めたスタッフがもう確定スタッフでない（外れた・退会した）ときは、取りこぼさないよう運営全員にメールする。
   - ベル通知は今までどおり運営全員。
6. **これまでの問い合わせのメールも変えた**（D-EVENT-CONTACT の「決定3：ベル通知だけ」を変更）:
   - 本人が始めた問い合わせ（新規・追記）は、運営全員（メール通知をオンにしている人）にメールも送る。
   - 運営の返信は、本人にメールも送る。

## データ

列は足していない（migration なし）。

- スレッドの持ち主 `inquiry.user_id` は**受け取るメンバー**。だから本人の一覧・スレッド・既読・返信がそのまま動く。
- 「運営から始めた」は**最初の発言**で決める: `inquiry_message.sender = 'staff'`。送ったスタッフはその発言の `author_id`。
  読むクエリが相関サブクエリで `started_by_staff` / `starter_id` を付ける（`inquiriesRepo` の `STARTER_SQL`）。
- 作ったときの状態は `answered`、`last_sender = 'staff'`。相手には未読、運営側は既読（`admin_read_at` を作成時刻に）。
- API の応答: 一覧（`Inquiry` / `AdminInquiry`）と詳細（`InquiryDetail`）に `startedByStaff`。運営側の詳細には `starterName`（送ったスタッフの表示名）。

## 画面

- 運営のイベントの「問い合わせ」一覧: 運営から始めた連絡に「運営から」の印。スレッドに「◯◯ さんが送った連絡」。
- 相手の「お問い合わせ」一覧: 同じく「運営から」の印。スレッドの見出しは「<イベント名> の運営からの連絡」。

## メールと Webhook のまとめ

| できごと | 相手（メンバー） | 運営 | Webhook |
|---|---|---|---|
| 運営が連絡を始めた | ベル＋メール | なし | 送らない |
| 運営が続けて書いた | ベル＋メール | なし | 送らない |
| 相手が返信した | なし | ベル（全員）＋メール（始めたスタッフ） | 「運営からの連絡への返信」 |
| 本人が問い合わせた・追記した | なし | ベル＋メール（全員） | 「問い合わせ」「問い合わせ（追記）」 |
| 運営が問い合わせに返信した | ベル＋メール | なし | 送らない |

メールは本人の通知設定（`notification_pref.email_enabled`）どおり。非公開イベントでは、今までどおり中立の文言になる。
