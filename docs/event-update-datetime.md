# イベントの部分更新と日時順 (#495)

PATCH /events/:id は startsAt / endsAt の片側だけを受け取る。
入力スキーマだけでは反対側の値が分からないため、日時変更を含むときに
保存済みイベントの値を補って、ルートで isDatetimeOrderInvalid を呼ぶ。
終了が開始より前になる更新は、DB更新・公開通知の前に invalid_date / HTTP 400 で拒否する。
一緒に送られたタイトルや公開状態も保存しない。

## 維持する契約

- 通常更新は作成と同じく開始＝終了を許す。
- scheduling:false を明示した直接確定は、従来どおり開始が正数かつ終了＞開始を要求する。
- 日時を含まない編集は新しい検証の対象にしない。
- 募集締切は既存の「更新後の状態」による検証を維持する。
- 認可・API入力形式・DBスキーマは変えない。既存データの一括補正はしない。

## 確認

実Workers/D1のテストで、変更前には逆転する3ケースがHTTP 200になってしまうことを再現。
変更後は同じケースでHTTP 400とDB未変更を確認する。
正常な片側更新、両側を同時に移動する更新、同時刻の境界、直接確定の厳しい条件も確認する。
日程調整・募集締切の既存テストを合わせて実行する。

本変更は通常のPATCH入力検証の欠落を補うもの。
ルートでの参照とリポジトリでの再参照・更新は既存どおり非原子的であり、
並行編集に対する排他・競合制御や既存不正データの修復は対象外とする。
