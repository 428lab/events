# ビンゴとイベントチャットの併設 (#499)

## 承認済みの範囲

参加者の会場 `/events/:id/bingo` と主催者の操作画面 `/events/:id/bingo/control` で、
抽選を見ながら同じイベントチャットを送受信する。PCは横並び、狭い画面は縦並び。
投影用 `/bingo/screen` は従来どおりで、名前や投稿操作を追加しない。
入口の見つけやすさは後続の #500 とし、本件では扱わない。

## なぜ共通の枠にするか

同じ会話でも抽選状態・参加者のカード・運営操作は別々に更新される。
BingoWithChatは配置と既存チャットへの接続条件だけを受け持ち、抽選の状態を持たない。
チャットに抽選番号をkeyとして渡さず、番号更新でも入力文や接続を維持する。
別イベントへ遷移した場合のみeventIdをkeyにしてチャットを切り替える。

## 幅と高さの責任

md以上ではビンゴを可変幅、チャットを360pxとする。md未満は1列にし、
ビンゴカードや文字を縮めずチャットを下へ置く。
チャット枠はモバイル520px、PCは表示高に追従（400〜720px）する。
EventChatのpage表示が履歴のスクロールと入力欄を分担する。
参加案内やエラーが増えた場合は外枠もスクロール可能にし、内容を隠さない。

## 権限と既存契約

useEventChatAccessの判定をそのまま利用する。公開・日程確定・チャット有効・
参加確定の条件を複製しない。既存の投稿可能時間帯・URL制限・締め出しの判定も
EventChat側に残す。サイト管理者フラグでイベント内の権限を広げない。
チャットを利用できない場合は案内のみとし、EventChatをマウントしない。
暗号処理の遅延読み込みを維持し、API・DB・マイグレーションは追加しない。

## 検証

両画面に実チャットUIを組み合わせ、外部の署名・リレー部分を差し替えて
受信表示、抽選更新中の入力保持、送信と入力クリア、閲覧のみの時間帯、
利用不可時の非接続を確認する。既存の抽選・チャット・投影テストも継続する。
レイアウトの実寸と入力欄への到達性はブラウザで確認する。
