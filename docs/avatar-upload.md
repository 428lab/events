# 本人アイコンのWebPアップロード (#511)

オーナー承認: PNG/JPEG/WebPの選択、正方形トリミングとプレビュー、WebP保存、SNS再ログインでの上書き防止。実装とstagingまで。本番は別承認。

## 保存と競合

- 設定/アカウント画面のプロフィールアイコンから選択。入力5MiB以内、8192px/辺・24M画素以内をクライアントでデコード検証。512×512のWebP（最大1MiB）に変換し、対応ブラウザーだけ保存可能。CanvasがPNGへフォールバックした場合は拒否する。
- `PUT /api/me/avatar` は認証中の本人のみ。サーバーもWebP MIME・マジックバイト・ヘッダー寸法512×512・1MiB上限を検証する。サーバーは画像のフルデコーダーではない。全体のストリーム上限は既存workerの8MiB。
- migration0087は `user.avatar_uploaded_key` のNULL許容列追加のみ。アップロードは固有R2キーへ書いてから、旧キー/旧更新時刻のCASでDB参照を差し替える。成功後に旧アップロード実体を削除。競合は409、DB失敗時は旧画像を保持。コミット済みか曖昧なエラーでは参照先を再確認し、現在画像は消さない。
- SNS同期は手動キーがある場合は取得前に終了。進行中だった同期もDB書き込みの条件で止め、SNSの固定キーと手動画像の固有キーを分離することでR2側の上書きも防ぐ。連携先URLは復旧用に保持し、SNS自体には書き込まない。
- 公開配信は既存のアバターURLを使い、手動キーを優先する。更新時刻は旧値より必ず進め、キャッシュ更新を促す。プロフィール・参加者一覧・名札は既存avatarUrl参照のまま。アップロード画像は公開されることをUIで明示する。
- アカウント統合・引き取りは削除後に手動キープレフィックスも掃除。退会の完全削除は書き込み不能な猶予期間後に同プレフィックスを列挙し、予算にlist回数を積む。中断で残った候補も対象。

## UX

既存のreact-easy-crop/cropToImageを利用し、ドラッグとズームで範囲を確認して保存。キャンセルは通信しない。保存失敗はダイアログと範囲を保持して再試行可能。保存中は閉じる操作を止める。元のアカウントやプロフィール設定は変更しない。
