# ビンゴ会場の入口 (#500)

## 承認済みの配置

受付中・抽選中はイベント詳細の説明・会場案内の直後、タイムテーブルより前に
専用セクションを置く。終了後はタイムテーブルの直後へ移す（staging確認後の追加指示）。
以前はチャット・Q&A・景品等の下に小さいテキストリンクとして置かれており、
参加者が会場へ進む入口を見つけづらかった。

既存BingoPanelを移動して強調し、別の案内を追加して二重表示にはしない。
見出しを「ビンゴ会場」とし、既存テーマのprimary色による罫線と大きい主ボタンで
通常の説明カードと区別する。独自配色や小さいフォントは追加しない。
スマホではボタンを全幅にし、狭い幅で2つの操作を横並びに詰め込まない。

## 状態と権限

受付中・抽選中・終了の状態、従来の人数と本人のリーチ/ビンゴ表示を維持する。
主ボタンは参加者会場へ向け、投影画面とは混同させない。
myRoleがstaffのときだけ副ボタンで抽選操作画面へ案内する。
サイト管理者フラグを混ぜず、ゲーム未作成時の既存スタッフ操作導線は残す。

イベント詳細の参加確定条件と、BingoPanelのゲーム有無の判定を維持する。
サーバーの認可・404による隠蔽、APIやDBは変更しない。
チャット併設 (#499) とは独立した変更として、専用画面の内容には触れない。

## 状態取得と配置変更

イベント詳細がビンゴ状態を1か所で取得し、配置とカードの内容に同じ値を渡す。
参加未確定なら取得を無効にし、キャッシュが残っていてもセクションは表示しない。
状態のポーリングは親に残すため、終了でセクションを上下に移しても作り直さない。
終了からリセットで受付中に戻った場合も上の配置へ戻し、常に1か所だけ描画する。

## 検証

実EventDetailPageと実BingoPanelをレンダリングし、周辺の副作用のみ置き換えて、
受付中・抽選中はタイムテーブルより前、終了後は直後というDOM順序と重複なしを検証する。
開いたまま終了・リセットした場合の配置切替も確認する。
状態・権限・ゲームなし・本人の達成・日英切替・リンク先も確認する。
ボタンの実寸とスマホ全幅、横はみ出しの有無はブラウザで別途確認する。
