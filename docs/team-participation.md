# コンテストのチーム参加（#9）

- 状態: 第1段の実装。オーナー決定（2026-10-24）「運営がチームの枠をつくってリーダーを立てる。参加者が好きなチームを選択する」
- 追加（2026-10-25）「チームの枠だけ作って、チームリーダーは運営が仮に決めるけどチーム内で決められるようにしてほしい。チーム名はチームリーダーが書き換えられるようにして欲しい」
- 対象: コンテスト形式（`contest_mode=1`）のイベントだけ。一般イベントは変わらない

## 使い方

### 運営（管理ページのコンテスト運営の下「チーム」）

1. 「チームで参加」をオンにする。オンにすると、採点・成果物・表彰がチーム単位になる
2. 「チームを作る」で枠を作る。チーム名・ひとこと・定員はどれも任意。名前が空欄なら「チーム1」「チーム2」…（そのイベントで使われていない最小の番号。英語の画面では「Team 1」…）が付く。名前はあとでリーダーが変えられる
3. 各チームの「リーダー」で、参加確定の参加者から仮のリーダーを選ぶ（空のままでもよい）。選んだ人は自動でそのチームのメンバーになる（別のチームにいれば移る）。運営はいつでもリーダーを変えられる
4. メンバーの「移動先」で、ほかのチームへ移したり、チームから外したりできる。採点が始まったあとも運営は動かせる
5. 「チーム未所属」には、まだどのチームにも入っていない参加確定の参加者が並ぶ。ここからチームに入れられる。未所属の人は採点・表彰の対象にならない
6. 空のチーム（メンバー・成果物・点数・受賞なし）だけ削除できる

### 参加者（イベント詳細「チームを選ぶ」）

- 参加が確定すると、チームの一覧（名前・ひとこと・メンバーとリーダー・人数／定員）が出て、「このチームに入る」で入れる
- 自分のチームには「あなたのチーム」が付き、「チームを抜ける」で抜けられる。ほかのチームは「このチームに移る」
- 満員のチームには入れない
- 採点が始まったら（採点の締切、または誰かの点が入ったら）、参加者は動けない。「採点が始まったので、チームを変えられるのは運営だけです」と出る
- 成果物は、チームのメンバーなら誰でも提出・編集できる

### チームの中（自分のチームのカード）

- リーダーには「チーム名を変える」（名前とひとこと）と「リーダーを任せる」が出る。任せる相手は同じチームのメンバーだけで、任せたあと元のリーダーはメンバーに戻る
- リーダーのいないチームでは、メンバーに「リーダーになる」が出る。先に押した1人がリーダーになる
- リーダーがいるチームで、メンバーがリーダーを取ることはできない（任せてもらうか、運営が変える）
- リーダーだけの権限は、名前・ひとことの変更とリーダーを任せることだけ。メンバーの追い出し・定員の変更・チームの削除は運営だけ
- どれも、チームを選ぶのと同じく採点が始まるまで。始まったら運営だけが変えられる
- 自分のチームは採点できない（既存の「自分のエントリーは採点できない」がそのまま効く）

### 発表・表彰式の大きなチーム名

- 発表画面の「発表中」と表彰式のカードでは、名前を見出しの幅に合わせて縮める（`apps/web/src/lib/entryNameFit.ts`。コンテナクエリの幅÷名前の幅の目安、最小24px〜最大48px）。「チーム・いぬ」くらいの名前は1行に収まる
- 最小まで縮んでも入らない長い名前だけが、文節（`auto-phrase`、非対応なら `keep-all`）で折り返し、それでも入らなければどこでも折る。はみ出さない

### 入館名簿CSV

- チーム参加のコンテストでは、「ロール」の直後に「チーム」（チーム名。未所属は空欄）と「リーダー」（リーダーなら○）の列が入る。人を表す列（ユーザー名・表示名・ロール）を先頭のまま保ち、出席の列は今までどおり並ぶ
- チーム参加でないイベント（一般イベント・個人参加のコンテスト、チームを残したままオフに戻したイベント）の名簿は、今までと同じ列

## データ

既存の「エントリー（参加単位）」抽象（docs/design.md §1）をそのまま使う。

| 何 | どこ |
| --- | --- |
| チーム参加のオン・オフ | 既存の `event.participation_type`（`individual` / `team`）。新しい列は足さない |
| チーム | `entry`（`kind='team'`）。名前は `entry.name` |
| ひとこと・定員 | `entry.description`（既定 `''`）、`entry.capacity`（NULL は上限なし）。migration `0115_event_teams.sql` で追加 |
| メンバー・リーダー | `entry_member`（`is_leader=1` がリーダー。1チーム1人） |

採点（`score`）・成果物（`submission`）・表彰（`award_result`）・発表中（`event_state.presenting_entry_id`）は、どれも `entry` を参照するので、チームはそのまま対象になる。

### 個人エントリーとの関係（切り替えでデータを消さない）

- 参加確定の経路（参加登録・繰り上げ・抽選・当落・日程確定の自動登録など）は、今までどおり個人エントリーを作る。チーム参加中も作られて残る
- 「いま使う種類」は `participation_type` で決める（`entries.ts` の `activeEntrySql`）。チーム参加ならチームだけ、それ以外は個人だけを、一覧・採点・集計・進捗・表彰の割り当て・発表中の指定・成果物の保存で使う
- そのため、チーム参加をオンにしても個人エントリーは消えず、オフに戻せば元のまま出てくる。チームもオフにしても消えない
- 切り替えは、そのイベントに点数・成果物・受賞がひとつもないときだけできる（`team_mode_locked`）。どちらかの種類に付いた点数や成果物が、見えないまま残るのを防ぐ

この方式にしたのは、参加確定の経路が7か所あり、どれも個人エントリーを作るため。チーム参加のときだけ作らないようにすると、全経路に分岐を入れることになり、取りこぼしがあると個人とチームが混ざる。作るのは今までどおりにして、使う側を1つの条件で絞るほうが安全。

### チームから外れるとき（トリガー）

参加確定の参加者でなくなったら（参加取消・当落・閲覧権限の取り消し・運営やスタッフへの変更・行の削除）、そのイベントのチームから外す。リーダーだった場合はリーダーも外れる（運営が立て直す）。参加し直しても、元のチームへは自動で戻らない。

経路が多いので、`event_member` のトリガー2本（`UPDATE OF role, status` と `DELETE`）に寄せた。アカウント統合で負け側の行が消えるときも同じトリガーで外れる。そのため、統合の重複でチームが2つになることはない（勝ち側の所属が残る）。

1人が同じイベントで入れるチームは1つだけ（トリガー `entry_member_one_team_per_event`）。移るときは、同じバッチで元のチームの行を消してから入れる。

### 退会

- 退会申請中のメンバーは、一覧のメンバー・リーダー・定員の数に入れない（既存の `memberUserIds` と同じ）
- 完全削除では `entry_member` が CASCADE で消える。チームのエントリーは共有物として残る（既存の「チーム参加は残す」）

## API（すべて `/api/events/:id/…`、ログイン必須）

| メソッド・パス | 誰が | 内容 |
| --- | --- | --- |
| `PUT /team-mode` `{enabled}` | 運営 | チーム参加のオン・オフ |
| `POST /teams` `{name, description?, capacity?}` | 運営 | チームを作る（201） |
| `PATCH /teams/:teamId` `{name?, description?, capacity?}` | 運営 | 変更。定員は今のメンバー数未満にできない |
| `DELETE /teams/:teamId` | 運営 | 空のチームだけ削除 |
| `PUT /teams/:teamId/leader` `{userId \| null}` | 運営 | リーダーを立てる・外す |
| `PUT /team-members/:userId` `{teamId \| null}` | 運営 | 入れる・移す・未所属に戻す |
| `POST /teams/:teamId/join` | 参加者 | 入る・移る |
| `DELETE /my-team` | 参加者 | 抜ける |
| `PATCH /my-team` `{name?, description?}` | 自分のチームのリーダー | 名前・ひとことを変える |
| `PUT /my-team/leader` `{userId}` | 自分のチームのリーダー | 同じチームのメンバーにリーダーを任せる |
| `POST /my-team/leader` | 自分のチームのメンバー | リーダーのいないチームで、リーダーになる |

- `POST /teams` の `name` は空欄でよい。空欄なら「チーム1」…。言語は `?lang=`（画面が今の表示言語を渡す）、無ければ Accept-Language で決める
- チームの中の操作は「本人がいまいるチーム」だけを触る（URLにチームIDを持たない）。リーダーか・同じチームのメンバーか・リーダー不在か・チーム参加か・採点前かは、書き込みと同じバッチの中で確かめる

- どれも応答は `{ entries }`（いま使うエントリーの一覧）。一覧は既存の `GET /entries` が返し、チームには `description`・`capacity`・`leaderUserId` が付く
- 条件（チーム参加か・採点前か・定員・参加確定か・そのイベントのチームか）は、書き込みと同じ D1 バッチの中で確かめる（`teams.ts`）。読んでから書くまでの間に状態が変わっても、何も書かれない
- エラー: `team_mode_off` / `team_locked` / `team_full` / `team_not_found`(404) / `not_participant` / `team_not_empty` / `team_mode_locked` / `capacity_below_members` / `not_team_member` / `team_has_leader`（409）、`not_team_leader`(403)
- 参加者の操作には、既存の `requireEventRole(["participant"])` を使う。運営は参加者ではないので、自分ではチームに入らない（採点対象としての運営の参加は、個人参加だけの既存機能）

## チームのスライド

チームごとに発表用のスライドを1つ持てる。チームのメンバーみんなで編集でき、成果物のプレゼン資料になる。

### 流れ

- 参加者: 「チームを選ぶ」の自分のチームに「チームのスライド」の欄が出る。まだ無ければ「チームのスライドを作る」（メンバーなら誰でも）。押すと「URLを知る人はログインせず閲覧できます（招待限定のイベントでも同じ）」と確認してから作り、編集画面へ移る。あれば「編集する」「見る」
- 作ると、チームの成果物のプレゼン資料 URL が空ならこのスライドの公開 URL（`/d/:slug`）が入る。入っていれば上書きしない
- 運営: チーム管理の各チームに「チームのスライド: 見る」（無ければ「まだありません」）。運営は見るだけで、編集はそのチームのメンバー
- スライドの一覧（`/decks`）には、自分の個人のスライドとは別に「チームのスライド」として「チーム: ○○（イベント名）」の札付きで出る

### 誰が編集できるか

- `deck.team_entry_id`（0118）でチームに結び付ける。1チーム1つ（部分 UNIQUE）
- 編集（取得・保存・画像のアップロード）は、そのチームの**いまの**メンバーだけ（チーム参加のコンテストで、イベントを見られる人）。抜けたら編集できなくなり、入った人は編集できる。作った人（`owner_id`）に特別な権限は無い
- チーム参加をオフにすると誰も編集できない（オンに戻せば元どおり）。スライドは消えない
- 削除はメンバーからはできない（作った人も）。1人がチームの作業を消してしまわないように。チームを消すと（空のチームしか消せない）結び付きだけ外れる
- 作った人が退会しても、チームのスライドは消えずに「退会済みユーザー」名義に移る（`deleteAccount` (1-e)）。個人のデッキは今までどおり消える
- 配信（ライブ）や発表者のスライドの指定は今までどおり「自分の個人のデッキ」だけ（`deck.owner_id` を見る）。チームのスライドは成果物の URL と公開ビューアで使う

### 同時に編集したとき

- `deck.revision` が保存のたびに 1 進む。編集画面は読み込んだ（最後に保存できた）版を `baseRevision` に添えて保存し、その間にほかの人（チームのメンバー・別のタブ・AI エージェント）が保存していたら `409 deck_conflict`（`revision`・`updatedAt`・`lastSavedBy` 付き）で止まる。**あとから保存した側が黙って上書きしない**
- 409 になると自動保存を止め、「ほかのメンバーが保存しました（○○さん・△分前）。この画面の変更はまだ保存されていません。最新を読み込むと、この画面の変更は消えます。」と出す。「この画面の内容をコピー」（JSON をクリップボードへ）と「最新を読み込む」を選べる
- チームのスライドでは「最後に保存: ○○さん・△分前」を出す（`deck.last_saved_by`。統合で勝ち側へ移す）
- 個人のデッキにも同じ仕組みが効く（`baseRevision` を添えない保存は今までどおり通る）
- 「いま○○さんが編集中」の表示は入れていない。定期的な取り直し（D-POLL-MIN）を増やさないと出せないため

| メソッド・パス | 誰が | 内容 |
| --- | --- | --- |
| `POST /api/events/:id/teams/:teamId/deck` | そのチームのメンバー | 作る（201）。あれば作らずに既存を返す（200, `created:false`）。応答は `{ deckId, created, entries }` |
| `GET /api/events/:id/team-decks` | 運営（全チーム）・参加者（自分のチーム） | `{ decks: [{ entryId, deck, canEdit }] }` |
| `GET /api/decks/team` | ログイン中 | 自分が編集できるチームのスライドの一覧 |
| `GET/PATCH /api/decks/:id`、`PUT /api/decks/:id/images` | 個人のデッキは持ち主、チームのスライドはいまのメンバー | 既存の編集の入口。PATCH は `baseRevision` を受け取る |

エラー: `not_this_team_member`(403)、`team_mode_off`(409)、`team_not_found`(404)、`deck_conflict`(409)、`team_deck_delete`(409)

## 今回入れないもの

- 参加者が自分でチームを作る・招待リンク・リーダーの追い出しや承認の権限（リーダーができるのは名前・ひとことの変更と、リーダーを任せることだけ）
- チームごとのチャットや連絡
- チーム参加の運営本人の参加（`SelfEntryParticipation` は個人参加のときだけ）
- イベント複製でのチームのコピー（複製は今までどおり個人参加で作られる）
- 公開プロフィールの受賞歴の表記の変更（チームで受賞しても、今までどおりメンバー各人の受賞歴に出る）
- チームのスライドの「いま○○さんが編集中」の表示・同時編集のマージ（保存がぶつかったら止めて選んでもらうだけ）
- チームのスライドを AI に書いてもらう（AI 用のトークンは個人のデッキだけ）・配信で使う
