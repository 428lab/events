# 編集画面（スライド / 配信セット）を責務ごとに分ける (#466)

- ステータス: **実装済み**（スライド編集は PR #468、配信セット編集は本ドキュメント
  と同じ PR）
- 対象: `apps/web`（`DeckEditorPage` / `LiveSetEditorPage` とその配下、
  `lib/editor/`、`lib/deckSlides.ts`、`lib/liveScenes.ts`）
- 前提: #466 は「1ファイル 800 行まで」の掃き出し。同じ方針で `EventDetailPage`
  を分けた PR #467 が先にマージ済み

---

## 1. なぜ分けたか

`DeckEditorPage.tsx` が 1106 行あった。ただ、溜まっていたのは「スライド編集の中身」
ではない。読んでみると**同じ仕掛けが 2 本ある**ことのほうが重い。

スライド編集（`DeckEditorPage`）と配信セット編集（`LiveSetEditorPage`）は、
履歴・自動保存・キーボード・キャンバス幅の計測・四隅リサイズの式・画像の差し込みが
**ほぼ字面まで同じ**だった。片方だけ直しても、もう片方は直らない。実際「まとめる猶予
500ms」「保存を待つ 800ms」「最小 20px」といった数字が 2 か所に散っていた。

なので、行数を削るために機械的に切るのではなく、

1. 2 か所にある契約を 1 つにする（`lib/editor/`）
2. 画面を描かずに確かめられる式を外へ出す（`lib/deckSlides.ts`）
3. 残った描画を、出し分けの条件ごと持って行かせる（`components/Deck*.tsx`）

の順で削った。結果として `DeckEditorPage` は 341 行になった。
続けて `LiveSetEditorPage`（1035 行）も同じ順で削り、**新しい仕掛けを作らずに
上の 1. を採用する**ことから始めた。採用した時点で履歴・自動保存・キーボード・
倍率・画像・四隅の式・採番の重複が消え、本体は 303 行になった。

## 2. どこで切ったか

**共通の仕掛け** (`apps/web/src/lib/editor/`)。編集対象の型を問わない形にしてある。

| 置き場所 | 何を持つか | なぜ 1 か所か |
| --- | --- | --- |
| `useEditorHistory.ts` | Undo/Redo。積む単位（連続変更を 1 手にまとめる猶予） | 「1 手」の定義が画面ごとに違うと、同じ操作で戻る量が変わる |
| `useAutoSave.ts` | 変更が落ち着いてからの保存。読み込み直後は投げない | 待ち時間と「開いただけで保存しない」の判断 |
| `useEditorKeyboard.ts` | 押されたキーを命令に翻訳。打っている最中は効かせない | 打鍵中に要素が消える事故を、片方だけ直して終わりにしない |
| `useCanvasScale.ts` | 実測幅から表示倍率を出す | 要素の座標を実寸で持つという前提そのもの |
| `useImagePicker.tsx` | 選ばせる・縮める・上げる・失敗を伝える | 「新しく置く」「差し替える」で入口が 2 つあるため |
| `resizeCorner.ts` | 四隅の変形の式と下限、ハンドルの逆補正 | 符号を 1 つ間違えると掴んだ隅と逆側が動く |
| `uid.ts` | クライアント側で振る id | 同上（採番の口を 2 つ持たない） |
| `collection.ts` | 並びの式（差し込む・入れ替える・重なり順・まとめて動かす・写す） | ページと要素の並びは両画面で同じ形。型ごとに書くと結果が食い違う |

**スライド固有**。`lib/deckSlides.ts` は React にも MUI にも依存しない純関数だけを置く。
残っているのはグループの扱い（まとめる・外す・選択の展開・写した側を別のグループに
する）と、置いたばかりの要素の既定値、そして選択の読み取り。
`components/DeckSlideList` `DeckLayerList` `DeckToolbar` `DeckCanvas`
`DeckElementPanel` が描画を持つ。

**配信セット固有**。`lib/liveScenes.ts` も同じく純関数だけ。シーンの名前の付け方
（新規の番号・「〜のコピー」）と、5 種類の要素（文字・画像・カメラ・スライド・
イベント情報）の既定値、背景が単色かどうかの判定。
`components/LiveSceneList` `LiveSceneToolbar` `LiveCanvas` `LiveElementPanel` が
描画を持つ。`ResizeHandles` は両エディタから使う。

## 3. 制約（次に触る人が守るもの）

- **`lib/editor/` に画面固有のものを入れない。** 入れた時点でもう一方が使えなくなり、
  分けた意味が消える。選択が単数か複数かのような差は、呼ぶ側から渡す。
- **並びの式は `lib/editor/collection.ts` に置き、型で書き分けない。** 差し込む・
  入れ替える・重なり順・まとめて動かすは `{id}` と `{id,x,y}` だけで書ける。
  `DeckElement` 用と `LiveElement` 用を別々に持つと、同じ操作なのに画面によって
  結果が違うという壊れ方をする。両画面固有として残ってよいのは、
  グループ（スライドだけ）と置いたばかりの要素の既定値だけ。
- **`deckSlides.ts` / `liveScenes.ts` に React を持ち込まない。** ここが純関数で
  あることが、並べ替えや重なり順を画面なしで確かめられる根拠になっている。
- **ドラッグ中は `content` を触らない。** `DeckCanvas` / `LiveCanvas` が
  一時的なずれだけを持ち、
  指を離した時に 1 回だけ確定する。一手ごとに書き換えると履歴が細切れになり、
  位置を渡し直された react-rnd と実際のドラッグ位置がぶつかって震える。
- **数字を画面側に書かない。** 猶予 500ms・保存 800ms・最小 20px・履歴 100 手・
  写しをずらす 20px は `lib/editor/` の各ファイルが 1 つずつ持つ
  （`useEditorHistory` / `useAutoSave` / `resizeCorner` / `collection`）。
  **2 か所あった状態は解消済み。** 画面側に書き戻すと、同じ操作なのに画面によって
  戻る量や保存の間合いが変わる。
- **`useCanvasScale` の ref を付ける要素は、呼ぶ部品の中で必ず描く。** 条件付きに
  すると最初の 1 回で `ref.current` が null になり、倍率が 0 のまま
  ＝真っ白なキャンバスになる。**エラーが出ないので気づけない。**
  読み込みを待つ必要がある画面は、待つ側（ページ）と測る側（`DeckCanvas` /
  `LiveCanvas`）を別の部品に分ける。そうすれば部品のマウント時＝要素がある時に
  測れる。以前あった `ready` 引数はこの形にしたことで渡す画面が無くなったので
  落とした（渡し忘れられる口を残さない）。

## 4. 残していること

- **`DeckCanvas` と `LiveCanvas` は 1 つにしていない。** スライド編集は複数選択と
  グループでまとめて動かす仕掛けを持つが、配信セットの選択は常に 1 つ。1 つにすると
  使わない分岐を配信側へ持ち込むことになる。**同じなのは倍率の出し方・変形ハンドル・
  ドラッグの確定の作法**で、そこは `lib/editor/` と `ResizeHandles` にある。
  配信セットに複数選択を入れるときが来たら、その時に寄せる。
- **配信セット編集の要素は一覧を持たない。** スライド編集のレイヤー一覧に当たるものが
  無く、**選ぶ手段がキャンバスしかない**。テストもそのため、幅を与えて描かれる状態を
  作ってから選んでいる（`LiveSetEditorPage.test.tsx`）。
- **キャンバス上の掴んで動かす操作は自動では確かめていない。** jsdom には寸法が無く、
  ドラッグそのものを追えない。式（`collection` / `deckSlides` / `liveScenes` /
  `resizeCorner`）と結線（`DeckEditorPage.test.tsx` / `LiveSetEditorPage.test.tsx`）を
  分けて押さえてある。
