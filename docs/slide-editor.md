# スライド編集画面を責務ごとに分ける (#466)

- ステータス: **実装済み**（PR は本ドキュメントと同じ）
- 対象: `apps/web`（`DeckEditorPage` とその配下、`lib/editor/`、`lib/deckSlides.ts`）
- 前提: #466 は「1ファイル 800 行まで」の掃き出し。同じ方針で `EventDetailPage`
  を分けた PR #467 が先にマージ済み
- 未着手: `LiveSetEditorPage`（1035 行）。本ドキュメントの 4. が引き継ぎ

---

## 1. なぜ分けたか

`DeckEditorPage.tsx` が 1106 行あった。ただ、溜まっていたのは「スライド編集の中身」
ではない。読んでみると**同じ仕掛けが 2 本ある**ことのほうが重い。

スライド編集（`DeckEditorPage`）と配信セット編集（`LiveSetEditorPage`）は、
履歴・自動保存・キーボード・キャンバス幅の計測・四隅リサイズの式・画像の差し込みが
**ほぼ字面まで同じ**だった。片方だけ直しても、もう片方は直らない。実際「まとめる猶予
500ms」「保存を待つ 800ms」「最小 20px」といった数字が 2 か所に散っていた。

なので、行数を削るために機械的に切るのではなく、

1. 2 か所にある契約を 1 つにする（`lib/editor/`）
2. 画面を描かずに確かめられる式を外へ出す（`lib/deckSlides.ts`）
3. 残った描画を、出し分けの条件ごと持って行かせる（`components/Deck*.tsx`）

の順で削った。結果として本体は 341 行になった。

## 2. どこで切ったか

**共通の仕掛け** (`apps/web/src/lib/editor/`)。編集対象の型を問わない形にしてある。

| 置き場所 | 何を持つか | なぜ 1 か所か |
| --- | --- | --- |
| `useEditorHistory.ts` | Undo/Redo。積む単位（連続変更を 1 手にまとめる猶予） | 「1 手」の定義が画面ごとに違うと、同じ操作で戻る量が変わる |
| `useAutoSave.ts` | 変更が落ち着いてからの保存。読み込み直後は投げない | 待ち時間と「開いただけで保存しない」の判断 |
| `useEditorKeyboard.ts` | 押されたキーを命令に翻訳。打っている最中は効かせない | 打鍵中に要素が消える事故を、片方だけ直して終わりにしない |
| `useCanvasScale.ts` | 実測幅から表示倍率を出す | 要素の座標を実寸で持つという前提そのもの |
| `useImagePicker.tsx` | 選ばせる・縮める・上げる・失敗を伝える | 「新しく置く」「差し替える」で入口が 2 つあるため |
| `resizeCorner.ts` | 四隅の変形の式と下限、ハンドルの逆補正 | 符号を 1 つ間違えると掴んだ隅と逆側が動く |
| `uid.ts` | クライアント側で振る id | 同上（採番の口を 2 つ持たない） |

**スライド固有**。`lib/deckSlides.ts` は React にも MUI にも依存しない純関数だけを置く。
ページの挿入・複製・削除・入れ替え、要素の重なり順・グループ・複製・選択の展開。
`components/DeckSlideList` `DeckLayerList` `DeckToolbar` `DeckCanvas`
`DeckElementPanel` が描画を持ち、`ResizeHandles` は両エディタから使える形にしてある。

## 3. 制約（次に触る人が守るもの）

- **`lib/editor/` に画面固有のものを入れない。** 入れた時点でもう一方が使えなくなり、
  分けた意味が消える。選択が単数か複数かのような差は、呼ぶ側から渡す。
- **`deckSlides.ts` に React を持ち込まない。** ここが純関数であることが、
  並べ替えや重なり順を画面なしで確かめられる根拠になっている。
- **ドラッグ中は `content` を触らない。** `DeckCanvas` が一時的なずれだけを持ち、
  指を離した時に 1 回だけ確定する。一手ごとに書き換えると履歴が細切れになり、
  位置を渡し直された react-rnd と実際のドラッグ位置がぶつかって震える。
- **数字を画面側に書かない。** 猶予 500ms・保存 800ms・最小 20px・履歴 100 手は
  `lib/editor/` の各ファイルが持つ。**ただしまだ 2 か所ある。** 配信セット編集は
  同じ 4 つを自前で持ったまま（`LiveSetEditorPage.tsx` の 140・144・155・344/348 行）。
  4. の採用が済むまで、**この 4 つを直すときは両方を直す**。片方だけ直すと、
  同じ操作なのに画面によって戻る量や保存の間合いが変わる。
- **`useCanvasScale` は測る要素が生えてから測る。** 読み込み中の早期 return より
  後ろにしか要素が無い画面（配信セット編集がそう）では `ready` を渡す。渡し忘れると
  倍率が 0 のまま＝真っ白なキャンバスになり、**エラーが出ないので気づけない**。

## 4. 残していること

- **`LiveSetEditorPage`（1035 行）は今回触っていない。** 同じ仕掛けを自前で持ったまま。
  次に分けるときは、新しく作らずに `lib/editor/` を採用する。採用した時点で、
  上の表の 7 つは重複が消える。シーン名・BGM・カメラ・イベント情報といった
  配信セット固有のものだけが残るはず。**採用時の注意が 2 つ**。`useCanvasScale` には
  `ready` を渡すこと（あちらは測る要素が早期 return の後ろにある）。選択が単数なので、
  `useEditorKeyboard` の `group` / `canGroup` は渡さない。
- **キャンバス上の掴んで動かす操作は自動では確かめていない。** jsdom には寸法が無く、
  描画そのものを追えない。式（`deckSlides` / `resizeCorner`）と結線
  （`DeckEditorPage.test.tsx`）を分けて押さえてある。
