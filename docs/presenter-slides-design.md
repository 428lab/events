## 1. 推奨モデル

**「登壇者本人が、自分が話すタイムテーブルのコマに、自分のデッキを1つ紐付ける」（案 a）。
配信コントロールはタイムテーブルから発表者一覧を作り、選ぶとそのコマのデッキが1ページ目で出る。**

### 1.1 紐付け方の比較

| 案 | 内容 | データの持ち主 | 本人の同意 | 当日の操作 | 判断 |
| --- | --- | --- | --- | --- | --- |
| **(a) 本人がコマに紐付け** | タイムテーブルの自分のコマに「この発表で使うスライド」 | 登壇者本人 | 紐付け＝同意。外せば撤回 | 選ぶだけ | **採用** |
| (b) staff が本人のデッキから選ぶ | staff に登壇者のデッキ一覧を見せる | staff | 無い。一覧に出た時点で slug が漏れる（デッキに非公開フラグが無いので中身まで読める） | 当日 staff が探す | 不採用 |
| (c) `material_url` から推定 | 資料URLが `/d/:slug` なら自動で使う | 登壇者本人 | 「公開した」ことが同意になるが、**本番前に参加者へ資料を公開する**ことが前提になる | 選ぶだけ | 不採用（補助としても入れない） |

(a) を選ぶ理由:

- **同意の単位が明確**。紐付けた本人が、このイベントのこのコマに限って staff に見せることを許す。
  他のデッキも、他のイベントも見えない。
- **既存の入口と同じ形**。#148 の「登壇者本人が自分のコマの資料URLを直す」と同じ場所・同じ権限判定
  （本人かつ現役メンバー、`public` の項目だけ）に並べられる。
- **一人で複数の発表**をしてもコマごとに別のデッキを付けられる（参加単位の紐付けだと1つしか持てない）。
- (c) は「公開資料」と「配信で映すもの」を混ぜる。発表前は資料を伏せたい人が使えない。
  URL の解釈（ドメイン・slug の取り違え）も持ち込む。

### 1.2 「発表者を選ぶ」とは

- **一覧の元はタイムテーブルだけ**。`speaker_user_id` が入っているコマを、タイムテーブルの並び
  （トラックを使うイベントは開始時刻順）で 1 コマ 1 行。同じ人の2本目は別の行になる。
- 担当者がフリーテキスト（アカウント未リンク）のコマは、灰色で「紐付け不可」と出す（選べない）。
- **イベントメンバー全員は出さない**。タイムテーブルに無い飛び入りは、staff がタイムテーブルに
  コマを足せば出る（未リンク者は従来どおり「その他のスライド」＝自分のデッキで対応）。
- 行には「スライドあり nページ」「スライド未登録」を出し、**事前確認がこの一覧だけで済む**ようにする。
- **選ぶと、紐付いたデッキが 1 ページ目で配信画面のスライド部分に出る**（`deckId` を差し替え、
  `deckPage = 0`）。紐付けが無ければスライド部分は「スライド未選択」になる。
  いま選ばれている発表者をもう一度押してもページは戻さない（誤タップで1ページ目に飛ばない）。
- **シーンは切り替えない**。シーン（「スライド + カメラ」など）は今までどおりシーン格子で選ぶ。
  発表者選択とシーン切替を混ぜると、カメラだけの発表で勝手に資料画面になる等の事故が起きるため。
- 従来の「自分のデッキから選ぶ」は「その他のスライド」として残す（運営のお知らせスライド用）。
  これを選ぶと発表者の選択は外れる。
- **#562 の参戦演出・氏名札とはつながない**。参戦演出は自由入力の演出文という設計なので、
  発表者を選んでも何も送らない。氏名札（配信セットの手入力テキスト）への名前の自動流し込みも
  今回はしない（§6）。

## 2. UX の流れ（日本語の画面文言つき）

### 2.1 登壇者が準備する（イベント前）

1. 登壇者は events lab でスライドを作る（既存のスライド機能）。
2. イベントのタイムテーブルを開くと、**自分がリンクされたコマ**にだけ
   「この発表で使うスライドを選ぶ」ボタンが出る（資料URLの鉛筆と同じ並び）。
3. 押すと自分のデッキがサムネイル付きで並ぶ（`/api/decks/mine` と同じ一覧）。1つ選んで
   「このスライドを使う」。
4. ダイアログの注意書き:
   > 選んだスライドは、**このイベントの運営スタッフが配信コントロールで表示・ページ送りできる**ようになります。
   > 参加者のタイムテーブルには出ません（公開したいときは今までどおり「資料URL」に載せてください）。
   > 紐付けを外すと、配信中でもすぐに表示されなくなります。
5. 紐付け後、そのコマには「配信スライド：（デッキ名）」のチップが出る（本人と staff にだけ見える）。
   「紐付けを外す」でいつでも外せる。デッキの中身は当日まで自由に直してよい（常に最新を映す）。

見本: `prototype.html#link`

### 2.2 staff が事前に確認する

1. 配信コントロールを開くと「発表者」一覧に各コマの状態が並ぶ。
2. 「スライド未登録」の人がいれば、本人に「タイムテーブルの自分のコマから選んでください」と頼む。
   **staff が代わりに選ぶことはできない**（同意の原則）。
3. 行を選べばプレビューと全ページの小さいサムネイルが見えるので、リハーサルで中身・ページ数を確認できる。

### 2.3 配信中

1. **発表者を選ぶ** → 「配信中」の印が付き、スライド部分にその人のデッキの 1 ページ目が出る。
2. 必要ならシーン格子で「スライド + カメラ」などに切り替える（従来どおり）。
3. **ページ送り**: ‹ › ボタン（従来）、**← / → キー**（今回追加。`DeckViewerPage` と同じキー。
   入力欄にフォーカスがあるときは効かない）、サムネイルを押して直接ジャンプ。
4. **次の発表者を選ぶ** → その人のデッキの 1 ページ目に替わる。

見本: `prototype.html#control`、配信画面は `prototype.html#screen`

### 2.4 例外

| 状況 | 画面の出方 | 運営の動き |
| --- | --- | --- |
| スライド未登録 | 行に「スライド未登録」。選ぶとプレビューに「この発表にはスライドが紐付いていません…」、配信画面のスライド部分は「スライド未選択」 | カメラのシーンで進める／「その他のスライド」から自分のデッキを出す |
| デッキが削除された | 紐付けは自動で消え（FK `SET NULL`）、未登録と同じ表示。配信中だった場合も `event_live_state.deck_id` が `SET NULL` で「スライド未選択」に戻る | 同上。本人に再登録を依頼 |
| 本人が紐付けを外した | 配信中なら次のポーリング（1秒）でスライド部分が「スライド未選択」になる | 同上 |
| 同じ人が複数の発表 | コマごとに1行。それぞれ別のデッキを付けられる。同じデッキを両方に付けてもよい | 行で選び分ける |
| staff が担当者を別の人に変えた | 前の担当者が付けたデッキの紐付けは消える（前の人の同意は新しい担当者のコマには及ばない） | 新しい担当者に付けてもらう |
| 担当者が退会・参加キャンセル | 一覧では「スライド未登録」扱い（現役メンバーのときだけ紐付けを有効にする） | — |
| 担当者がアカウント未リンク（フリーテキスト） | 「紐付け不可」で選べない | 「その他のスライド」で対応 |

## 3. データと権限

### 3.1 マイグレーション `0100_presenter_slides.sql`

```sql
-- #571 登壇者本人がこのコマに紐付けた配信用デッキ（このイベント・このコマ限定の公開同意）
ALTER TABLE event_schedule_item ADD COLUMN live_deck_id TEXT REFERENCES deck(id) ON DELETE SET NULL;
-- #571 配信コントロールでいま選ばれている発表（コマ）
ALTER TABLE event_live_state ADD COLUMN presenter_item_id TEXT REFERENCES event_schedule_item(id) ON DELETE SET NULL;
```

- 新しい表は作らない。どちらも **user を参照しない列**なので、`userTables.ts`
  （退会・統合の登録）と `user-tables.test.ts` / `merge-user-columns.test.ts` の追加は不要。
  - 退会: `deck` が owner CASCADE で消え、`live_deck_id` は `SET NULL`。`speaker_user_id` も
    `SET NULL`。孤児も FK による削除ブロックも起きない。
  - 統合: `deck.owner_id` と `event_schedule_item.speaker_user_id` はどちらも既に勝ち側へ
    付け替えられるので、「担当者＝デッキの持ち主」の関係はそのまま保たれる。
- `presenter_item_id` を持つ理由: コントロールを複数人・複数タブで開いても「いま誰の番か」を
  同じに見せるため。`deckId` からの逆算では、紐付けが無い発表者・同じデッキを2コマに付けた場合を
  区別できない。
- 0092 のカード再生成トリガーは `UPDATE OF event_id,speaker_user_id,visibility,placement` に
  限られるので、`live_deck_id` の更新では発火しない。

### 3.2 「紐付けが有効」の定義（1か所だけに書く）

コマ `i` のデッキ `d` を配信に使ってよいのは、次がすべて成り立つときだけ:

1. `i.event_id` がこのイベント、`i.visibility = 'public'`
2. `i.live_deck_id = d.id`
3. `d.owner_id = i.speaker_user_id`（**紐付けた本人のデッキであり、いまも担当者である**）
4. `i.speaker_user_id` がこのイベントの現役メンバー

これを `presenterSlidesRepo`（仮称）の 1 つの SQL にまとめ、一覧・選択・読み出しのすべてが使う。

### 3.3 API

| エンドポイント | 誰が | 内容 |
| --- | --- | --- |
| `PUT /api/events/:id/timetable/:itemId/live-deck` `{ deckId: string \| null }` | **設定**: そのコマの担当者本人（現役メンバー）だけ。**解除**（`null`）: 本人または staff | 設定時は `deck.owner_id = 自分` を確認。対象は `public` の項目だけ（#148 と同じ）。解除したデッキが配信中なら、同じ書き込みで `event_live_state` の `deck_id` を `NULL` にする |
| `GET /api/events/:id/live-presenters` | staff（既存の `requireEventRole(["staff"])`） | 発表者一覧: `{ itemId, title, startsAt, speaker, deck: { id, title, slideCount } \| null }[]`。デッキは §3.2 で有効なものだけ。**slug は返さない** |
| `PATCH /api/events/:id/live-state` に `presenterItemId` を追加 | staff | **クライアントはデッキ ID を送らない**。サーバが §3.2 でデッキを解決し、`presenter_item_id` / `deck_id` / `deck_page = 0` を1回で書く（同じコマの再選択ではページを保つ）。`deckId` を直接送った場合は `presenter_item_id` を `NULL` にする |
| `GET /api/events/:id/live-deck-content` | staff | **変更しない**。`state.deckId` を描く今の経路で非公開デッキも描ける |

- 担当者変更時の解除: `saveAll` の既存項目 `UPDATE` に
  `live_deck_id = CASE WHEN speaker_user_id IS ? THEN live_deck_id ELSE NULL END`
  を足す（staff の全体保存で列そのものは書かない＝本人の紐付けを staff が上書きできない）。
- 一般的なデッキの読み取り権限（`/api/decks/:id` の owner 限定、`/mine`）は**広げない**。
  staff は一覧で他人のデッキの slug も一覧も見ない。中身が届くのは「配信中に選ばれたデッキ」を
  `live-deck-content` が描くときだけ。
- 付随する締め付け（提案）: `PATCH live-state` の `deckId` 直接指定は
  「操作者自身のデッキ」に限る。いまは任意の ID を書けて `live-deck-content` で中身を読めてしまう
  （UUID なので推測は難しいが、同意の境界としては穴）。UI は自分のデッキしか送らないので
  既存の操作は変わらない。
- D1 への変更はこのマイグレーション（列追加 2 つ）だけ。

## 4. ページ送り

- 既存の `deckPage` と ‹ › ボタンをそのまま使う。画面側は変更なし。
- **← / → キー**をコントロールに足す（今のコントロールには無い。キーは `DeckViewerPage` と揃える。
  Space はページのスクロールやボタン押下とぶつかるので入れない）。
- サムネイル列を押すとそのページへ飛ぶ（`deckPage` を直接書くだけ）。
- **登壇者本人のスマホからのページ送りは今回は入れない**。後で入れるなら
  「`presenter_item_id` のコマの担当者本人だけが `deckPage` を書ける」エンドポイントを 1 つ足す形で、
  今回のデータに追加の列は要らない。

## 7. オーナーに確認したいこと

1. **発表者を選んだらシーンも「スライド + カメラ」に自動で切り替えるか。**
   推奨は「切り替えない」（カメラだけの発表で勝手に資料画面にならないように）。
2. **発表者一覧はタイムテーブルのコマだけでよいか。**
   飛び入りはタイムテーブルにコマを足してもらう運用でよいか（推奨: それでよい）。
3. **staff が登壇者の紐付けを「外す」ことは許すか。**
   推奨は「外すのは可・付けるのは本人だけ」（外すのは公開範囲を狭める方向なので同意を損なわない）。
4. **登壇者本人のスマホでのページ送りは次の段階でよいか。**
