# スタッフを参加枠に並べる・運営が割り当てる枠

オーナー判断（2026-10-29）。
- 「枠を作る前に参加していたスタッフが、あとから枠を作ると移動もできず『その他』に出る」→ 運営がスタッフ等を好きな枠の下へ移せるようにする（案A：表示だけ、席は使わない、1人1枠）。
- 「運営割り当てしか入れない枠を作れると安心」→ 枠ごとに「運営が割り当てる枠（参加者は選べない）」を付けられるようにする。

## 使い方

- **スタッフを枠へ移す**：参加者一覧で、スタッフ・審査員・観覧者の行の「…」→「並べる枠」から枠を選ぶ。「枠なし（その他）」で戻せる。参加者の行には出ない（参加者の枠は本人の申込で決まる）。
- **運営が割り当てる枠**：イベント編集の参加枠で、枠ごとのスイッチ「運営が割り当てる枠（参加者は選べない）」をオンにする。追加するときにもオンにできる。

## データ（migration 0116）

| 列 | 意味 |
| --- | --- |
| `event_member.assigned_slot_id` | 参加者以外のロールを一覧のどの枠の下に並べるか。表示だけ。FK は枠の削除で NULL |
| `participation_slot.staff_only` | 運営が割り当てる枠。0/1、既定 0 |

`slot_id`（参加者が申し込んだ枠）は今までどおり参加者だけが持つ（#277）。スタッフ等を枠に並べても `slot_id` は NULL のまま。

## 席を使わないことの保証

定員・先着の確定/キャンセル待ち・抽選・繰り上げ・在籍数（0108 の `cnt_*` トリガー）は、どれも `slot_id` だけを数える。`assigned_slot_id` はどこからも数えないので、満員の枠や抽選枠にスタッフを並べても、席・抽選・キャンセル待ちは変わらない。名札の枠別デザインと一斉連絡の枠別宛先も `slot_id` だけを見るので、並べたスタッフは含まれない（今までどおり「スタッフ」として扱う）。

`assigned_slot_id` は user を参照しないので、アカウント統合・退会の登録（`userTables`）は要らない。

## 運営が割り当てる枠のルール

- 参加者の申込（`POST /events/:id/join`）でこの枠を指定すると `409 slot_staff_only`。SQL の側（`joinEventAtomically`）でも同じ条件で弾く。
- 参加者が選べる枠が1つも無い（運営の枠だけの）イベントは、枠なしで参加する（枠が無いイベントと同じ）。
- 日程確定の自動登録（`scheduleRegistration`）は、参加者が選べる枠だけを見て枠を決める。
- 画面：参加者の申込の選択肢には出さない。参加者一覧では見出しとして出る（並べたスタッフ等がいるとき）。
- イベントの「参加 n / 上限」：上限にこの枠の定員は入れず、代わりにこの枠にいる確定メンバー数を足す（分子と母集団を揃える）。保存済みカウンターは変えず、読む式（`EVENT_COUNTER_COLUMNS` / `CAPACITY_TOTAL_SQL`）で差し替える。参加者が選べる枠が無ければ上限なし。
- 抽選・キャンセル待ち・定員は使わない（参加者が新しく入らないため）。
- **オンにしたときに、すでにこの枠を選んでいた参加者はそのまま残る**（データは消さない）。止まるのは新しい申込だけ。

## ロールが変わったとき・抜けたとき

- 参加者に戻る（ロール変更・取消後の再参加・自動登録など、どの経路でも）：トリガー `event_member_clear_assigned_slot` が `assigned_slot_id` を消す。
- 参加者→スタッフ・審査員・観覧者（ロール変更・スタッフ招待の承諾・アカウント統合での引き継ぎ）：今までどおり `slot_id` を外して確定にし、席を空けてキャンセル待ちを繰り上げる（#277 / #281）。そのとき申し込んでいた枠は `assigned_slot_id` に移すので、一覧では同じ枠の下に並んだまま。同じ UPDATE の `assigned_slot_id = COALESCE(slot_id, assigned_slot_id), slot_id = NULL` で書く（SQLite の SET の式は更新前の行で評価される）。枠なしの参加者は割り当ても無し（その他）。取消済みの行から戻るときは前の枠を持ち込まない。
- 参加者以外のロール同士の変更（スタッフ→審査員など）：`assigned_slot_id` はそのまま。
- 参加の取消・行の削除：行ごと消えるか、取消の行は一覧に出ないので影響しない。
- 枠の削除：FK で `assigned_slot_id` が NULL になり「その他」に戻る。

## API

- `PATCH /api/events/:id/members/:userId/assigned-slot` `{ slotId: string | null }`（staff のみ）。参加者の行は `409 participant_slot`、他イベントの枠は `404 slot_not_found`。
- `POST/PATCH /api/events/:id/slots` に `staffOnly?: boolean`。枠の一覧に `staffOnly` が付く。

## 入れていないもの

- 1人が複数の枠に同時に入る（案B）。
- 参加者を運営が枠へ移す操作（参加者の枠は申込・抽選の結果なので、今回は触らない）。
