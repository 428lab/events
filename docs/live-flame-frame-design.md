# 配信用「炎のフレーム」デザイン案 (#566)

配信画面のカメラ・資料・画面全体を炎で囲む装飾パーツ「炎のフレーム」のデザイン案です。
本書はデザイン提案であり、製品コードへの実装は含みません（オーナー確認後に別途実装します）。

- 試作: [`docs/assets/live-flame-frame-566/prototype.html`](assets/live-flame-frame-566/prototype.html)（1 枚の canvas に WebGL のシェーダーで描きます。外部ライブラリ・画像・通信なし。ブラウザで直接開けます）
- 掲載している画像はすべて試作の見本です。スライド・カメラ・氏名はダミーで、実イベント画面での動作を示すものではありません。

## パーツ名

- 表示名: 「炎のフレーム」

## 囲む場所

| 囲む場所 | 内容 |
| --- | --- |
| カメラ | カメラ枠の外周を炎で囲む |
| 資料 | スライド（資料）枠の外周を炎で囲む |
| 画面の縁 | 画面全体の縁取りとして四辺に炎を置く |

- 「中の人や資料が燃やされている」ではなく「**枠そのものが燃えている**」見え方にする。そのため炎は重力を無視し、枠から**外側へ放射状に**広がる。
  - 上辺は上へ、下辺は下へ、左辺は左へ、右辺は右へ、角は斜め外へ向く（角丸に沿って向きがなめらかに変わる）。
  - 炎の舌は枠から外へ流れ続け、途中で割れたり、巻いたり、ちぎれて消えたりする。火の粉も上へ昇るのではなく、枠から外へ飛び出していく。
- 枠の内側（カメラ映像・資料の本文）には何も重ねない。枠の線から内側は完全に透明にする（光のにじみも入れない）。
- 画面の縁では、画面の端から少し内側に枠の線を置き、炎はその線から**画面の端へ向かって外向きに**伸びる（画面の外へはみ出してよい）。中央の安全領域には届かない。
- 中央は常に空け、顔や本文を隠さない（試作の「安全領域を表示」で確認できる）。

## 炎の見え方（TV 番組の演出に近づける）

板状の炎の形を並べて同じ動きを繰り返す方式はやめ、画素ごとに炎を計算して描く（手続き的な炎）。

- **連続した炎の舌**: 枠（角丸の四角形）からの外向きの距離と、外周に沿った位置を画素ごとに求める。この座標でゆがめた乱流ノイズ（ドメインワープした fbm、5 オクターブ）を外へ流し、炎の舌が途切れずに外へ流れ出るようにする。
- **繰り返しが見えない**: 外周に沿った位置は角も含めて 1 周でつながる値にし、ノイズもその 1 周で周期を持たせる。つなぎ目や同じ形の並びが出ない。舌の長さ・太さも場所と時間でゆっくり変わる。
- **温度の色**: 枠ぎわは白〜黄の芯、外へ行くほど橙→深紅→透明な煙の縁に変わる。
- **光**: 縮小した画像をぼかして足すグロー（ブルーム）と、炎の先だけのかげろう（熱による揺らぎ）。枠の線は揺らさない。
- **フレア**: ときどき明るい盛り上がりが枠に沿って走る。
- **火の粉**: 小さな明るい粒が枠から外へ飛び出し、瞬きながら横に流され、消える。
- **背景は透明**（事前乗算アルファ）。OBS でどの画面にも重ねられる。

## 色

温度に応じた 5 段の色の変化（煙の縁 → 深い色 → 中間 → 明るい色 → 芯）で描く。

| 色名 | 芯 → 縁 | 重ね方 |
| --- | --- | --- |
| 赤橙 | 白〜黄の芯 → 橙 `#F2560F` → 深紅 `#A3170A` → 透明 | 光を足す見え方 |
| 青 | 白〜水色の芯 → 青 `#1F6BFF` → 深い青 `#0B2AA6` → 透明 | 光を足す見え方 |
| 紫 | 白〜桃色の芯 → 紫 `#A33CFF` → 菫色 `#5A0FA8` → 透明 | 光を足す見え方 |
| 白磁の金 | 淡い金の芯 → 金 `#BC7E1C` → 琥珀 `#94580F` → 透明 | 白い地で白飛びしないよう、光を足さずに普通に重ね、縁を暗めの琥珀色にする。炎はやや低めにする |

既定は「赤橙」。

## 設定項目

| 項目 | 範囲 | 刻み | 既定値 |
| --- | --- | --- | --- |
| ゆらぎの強さ | 0–100 | 5 | 60 |
| 炎の高さ | 16–72 | 2 | 44 |
| フレームの太さ | 2–12 | 1 | 4 |
| 角丸 | 0–48 | 2 | 16 |
| 火の粉の量 | 0–100 | 5 | 50 |

- ゆらぎの強さは、乱流の強さと炎が外へ流れる速さの両方を変える。

試作は URL パラメータ（`theme` / `place` / `flicker` / `height` / `thickness` / `radius` / `embers` / `pause=1` / `motion=reduce` / `guide=1` / `view=output` / `t=秒`）でも同じ状態を再現できます。炎は時刻だけで決まるので、`t=秒` を付けるとその時刻の 1 コマを必ず同じ形で描きます（撮影・動画の書き出し用）。

## 動きの配慮

- **動きを減らす**: OS の「視差効果を減らす」（`prefers-reduced-motion: reduce`）または設定で、決まった時刻の 1 コマだけを描いて止める（描画ループを回さない）。
- **編集中のプレビュー**: 編集画面では一時停止でき、描画ループを止めた状態で配置や色を確認できる。
- ゆらぎの強さを下げると揺れが小さく・遅くなる。

## 性能

- 炎は 1 枚の canvas に描く。canvas は枠の外接矩形に炎の高さぶんの余白を足した範囲だけを覆い、画面全体は覆わない（カメラ・資料のとき）。
- 解像度は端末の画素密度に合わせるが、上限を約 140 万画素にする。画面の縁のときは半分の解像度で描いて拡大する。
- 1 コマは 3 段の処理: 炎（ノイズ 5 オクターブ＋ゆがみ用 2 オクターブ×2）→ 1/4 解像度のぼかし 4 回（グロー）→ 合成（かげろう・内側を透明にする）。DOM の要素数は増えない。
- 外部ライブラリ・画像ファイル・通信を使わない（ネットワーク資源なし）。
- 計測（試作、1920×1080 のヘッドレス Chromium、`bench`＝同期読み出し込みの 1 コマ時間）:

| 条件 | canvas | Apple M3 Max（Metal） | SwiftShader（ソフトウェア描画） |
| --- | --- | --- | --- |
| 赤橙・カメラ（既定） | 944×920 | 2.1 ms（実描画 120 fps で頭打ち） | 43.8 ms（約 18–23 fps） |
| 紫・画面の縁（半分の解像度） | 960×540 | 1.7 ms（120 fps） | 25.0 ms（約 40 fps） |
| 最大設定（高さ 72・太さ 12・角丸 48・火の粉 100） | 1122×1080 | 2.3 ms（120 fps） | 90.0 ms（約 11 fps） |

  - GPU があれば十分軽い。GPU を使えない環境（ソフトウェア描画）ではカメラ枠で 20 fps 前後まで落ちるため、製品化では描画解像度をさらに下げる逃げ道（例: 半分の解像度）を用意する。

## 実装の見立て（提案）

- 既存の配信セットの `LiveElement`（`type: "motif"`）の装飾モデルに、新しいモチーフ（例: `motif: "flameFrame"`）として追加する。
  - `packages/shared/src/liveSets.ts` のモチーフ種別 enum に 1 つ追加し、色・ゆらぎ・高さ・太さ・角丸を最小限の任意項目として足す。
  - 既存のモチーフ（lantern / halo / brackets / grid / ticks）や既存の配信セットはそのまま読み込めるよう、追加項目はすべて任意・既定値ありにする。
- 動きの許可範囲（装飾の動きのみ）と表示範囲の検証は既存の仕組みに合わせる。
- 描画は既存の配信画面・編集画面のモチーフ描画に 1 種類追加する形とし、動きを減らす設定と編集中の一時停止を尊重する。
- 炎のフレームは **1 つの canvas を持つライブ要素**として描く（多数の DOM 要素は作らない）。配信セット編集画面では、ほかのパーツと同じく選択・移動・設定の変更ができる 1 つのパーツのままにする。
  - canvas の位置と大きさは囲む枠から計算し、枠の内側は常に透明にする。
  - WebGL が使えない環境では炎を描かず、枠の線だけにする（試作では注意書きを表示）。
